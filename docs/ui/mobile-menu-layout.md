# 移动端菜单布局

所有游戏子菜单共享 `src/UI/Mobile/game/MenuLayout.css`，分类与浮层边界计算位于 `MenuLayout.js`。业务样式只负责窗口内部排版，不再定义外框尺寸或独立的设备断点。

## 尺寸策略

屏幕短边至少 600 CSS 像素的平板始终使用 spacious；手机在可用布局视口宽至少 768、高至少 560 CSS 像素时使用 spacious，其余使用 compact。软键盘打开期间保持原密度，窗口适配可视高度。

| 窗口 | 平板上限 | 手机 |
| --- | --- | --- |
| 普通子菜单、冒险工具 | 宽 1040；横屏高 640，竖屏可用区域的 72% | 保留紧凑尺寸，受安全区域约束 |
| 主菜单 | 宽 560，高 640 | 宽 420，内容自适应 |
| 确认、消息弹窗 | 420×480 | 同样受可视区域约束 |
| 装备选择弹窗 | 宽 640 | 同样受可视区域约束 |
| 输入编辑器 | 宽 420，单行高 160、多行高 320 | 竖屏居中卡片，横屏全屏顶部输入条 |

所有尺寸均为上限；边距、安全区域和键盘可视高度优先。普通子菜单平板统一高度；短确认弹窗按内容缩小。

## 接入规则

- 外层使用 `mobile-menu-viewport`，窗口使用 `mobile-menu-window`；在业务样式之后加载 `MenuLayout.css`。
- 宿主通过 `createMobileViewport` 或 `bindMobileViewport` 更新视口和密度，销毁时释放监听。独立消息弹窗使用 `mobile-menu-dialog`。
- 标题和操作栏不能收缩；可滚动内容必须设置 `min-height: 0`，滚动发生在内容内，不能让整个窗口超出视口。
- 控件使用 `--panel-control`、`--panel-label`、`--panel-heading`、`--panel-gap`。需要调整统一尺寸时仅修改中心样式中的 token；手机特殊宽度也集中登记在这里。
- 冒险工具内部列布局使用 `menu-content` 容器查询，逻辑通过 ResizeObserver 读取实际窗口宽度，不能根据设备宽度猜测内容宽度。
- 菜单和冒险工具下拉框共用 `GameSelectLayout.js`，使用 Popover 顶层显示，按可视视口限高，优先向下展开，允许超出小弹窗边界，避免被滚动容器或 containment 裁切。视口平移／缩放、外部点击、父容器滚动及窗口销毁时关闭浮层；列表自身滚动保持展开。

## 验证

覆盖窄屏竖屏、手机横屏、平板横竖屏、桌面尺寸下的移动 UI、分屏及低高度视口；检查最长内容、下拉框、二级弹窗及键盘开合。PWA 必须使用 `npm run build:pwa` 完整构建，保留启动页与全部查看器。

## 字号与组件密度

字号和通用控件尺寸由 `MenuLayout.css` 统一定义；冒险工具与其它子菜单共用，不再定义独立的字号比例。业务样式根据内容角色选用变量，不根据具体文案单独加大或缩小。

| 角色 | 共享变量 | 手机 | 平板 |
| --- | --- | --- | --- |
| 正文、详情说明 | `--panel-text` | 12px | 16px |
| 分节标题 | `--panel-heading` | 12px | 16px |
| 窗口主标题、详情名称 | `--panel-title` | 14px | 18px |
| 辅助信息、字段标签 | `--panel-label` | 11px | 14px |
| 次要提示 | `--panel-caption` | 10px | 14px |
| 通用按钮、输入框高度 | `--panel-control` | 30px | 44px |
| 素质加点按钮高度 | `--panel-attribute-control` | 26px | 44px |
| 素质加点按钮宽度 | `--panel-attribute-width` | 32px | 56px |

- NPC、出现地图、掉落物品、职业、等级与点数等均属于分节标题，不能各自硬编码字号。
- 按钮内边距使用 `--panel-control-padding`；布局间距使用 `--panel-gap`。表格、列表和分栏仍由业务样式负责排版。
- 图鉴列表、魔物详情、物品详情的图片尺寸和缩放参数集中登记为 `--panel-list-image-scale`、`--panel-detail-image`、`--panel-detail-image-scale` 和 `--panel-item-image`。精灵图原始裁切尺寸保持不变，通过等比缩放放大，避免错位。
- 箭头等图形字符可保留自己的视觉尺寸；它们不属于正文排版。聊天等既有专用控件可保留已定义的功能布局。

手机宠物、生命体、佣兵和银行与背包等普通子菜单共用 780px 宽度上限及安全区域内全高；生命体与佣兵共用 companions 窗口，不再保留 420px 小窗例外。

## 按内容宽度自适应

`MenuLayout.js` 统一维护 `data-menu-density`、`data-orientation` 和 `data-menu-arrangement`。密度决定字号和控件大小，真实方向决定窗口高度，菜单排列决定内部结构。手机竖屏使用 `stacked`，其余使用 `wide`。软键盘打开时保持排列与密度，只更新可视高度。

`MenuContentLayout.css` 提供公共分栏；`MenuContentComponents.css` 处理工具栏、边框、图片和详情；`MenuPortrait.css` 处理真实方向对应的高度及手机上下布局的拾取操作排列。各功能排列通过 `*MenuLayout.css` 补充。

| 条件 | 布局规则 |
| --- | --- |
| 手机竖屏 `stacked` | 列表、详情按各菜单的手机布局上下排列，筛选与操作区按已确认位置展示 |
| 手机横屏、平板横竖屏 `wide` | 保持横向列表／详情、表单分栏及工具栏，不套用手机上下布局 |
| `stacked` 详情宽度小于 540px | 地图／NPC 内部详情上下排列，魔物资源单列 |
| `stacked` 详情宽度小于 460px / 360px | 角色维护表单改单列／图片与描述上下排列 |
| 快捷位置按钮宽度小于 64px | 仅显示位置数字，保留完整无障碍标签 |

平板竖屏标准窗口使用安全区域内可用高度的 72%，横屏保留 640px 上限；首页按内容自适应。旋转只更新布局属性，不重建业务组件，不丢失选中项和输入草稿。

拾取搜索弹窗宽度上限为手机 420px、平板 640px，手机竖屏高度为可视区域的 80%，平板竖屏为 64%；平板两个方向保留横向操作排列，手机竖屏使用独立的搜索与底栏布局。

游戏顶部通知使用 HUD 实际底边提供的共享通知位置，避开人物信息、小地图和方向提示条；横屏和 HUD 移除后恢复原位置。

验收覆盖 320×568、390×844、507×1024（平板分屏）、600×960、768×1024、820×1180、1024×1366，以及 844×390、1024×768 横屏。检查外层与内层分栏、横向溢出、操作区和滚动可达性、切换后的选中状态。复杂交易流程还需在实际容器宽度与控制密度组合下单独验证。

## 新组件的布局接入

外框、密度、方向仍由 `MenuLayout.js` / `MenuLayout.css` 管理。内容分栏通过组件声明选择，公共 CSS 不再枚举背包、装备等业务类名。

| 声明 | 内容结构 | 适用场景 |
| --- | --- | --- |
| `data-menu-layout="split"` | 两个直接子区域 | 列表＋详情；窄窗口上下各占一半 |
| `data-menu-layout="form"` | 两个直接子区域 | 表单＋结果；宽松密度采用 800px 阈值 |
| `data-menu-layout="columns"` | 两栏或三栏 | 仓库、交易、精炼等流程 |
| `data-menu-layout="shop"` | 列表、操作区、订单、详情 | 带中间操作区的商店流程 |

例如：

```html
<div class="example-layout" data-menu-layout="split">
  <section class="example-list">列表</section>
  <section class="example-detail">详情</section>
</div>
```

组件负责宽屏默认列比例、内容和自身装饰；公共布局负责现有断点下的列切换、区域约束和滚动。不要为新业务组件在公共布局里追加类名，也不要复制一套设备判断。

多栏流程通过 `interactionColumns(body, columns)` 创建，该函数自动声明布局及 `data-menu-columns`。两栏模式的宽屏样式和中等宽度行为都从同一个列数声明读取，调用方无需额外添加“两栏”样式类。

样式顺序固定为：业务基础样式 → 共享外框与控件 → 方向相关样式 → `MenuContentLayout.css` → `MenuContentComponents.css`。公共文件只维护布局协议；专属规则在组件文件中调整，避免让新组件隐式继承其它业务的图片或按钮样式。本轮重构保留原有断点、选择器权重、尺寸与视觉值。

手机端冒险工具物品页的顶部搜索栏固定两行：第一行搜索，第二行类型、子类和发放 Zeny。`AdventureTools.js` 依据屏幕短边小于 600 CSS 像素设置局部 `data-phone-screen` 标记，仅用于该搜索栏；平板窄分屏与软键盘不会因此套用手机规则，窗口尺寸及其它内容继续遵循共用布局。

## 样式职责与复用

移动菜单的样式按以下顺序加载，后面的菜单规则只负责内容排列，不重新定义公共控件高度。

| 文件 | 职责 |
| --- | --- |
| `MenuLayout.css` | 视口、密度、字号及尺寸变量 |
| `MenuChrome.css` | 标题栏、底栏高度、按钮组与内容区边界 |
| `MenuFeatureStyles.js` 与各 `*MenuLayout.css` | 各菜单横竖屏排列、滚动区域与业务内容 |
| `MenuBottomTabs.css` | 底部标签行的分隔线与对称留白 |
| `MenuFormControls.js` / `.css` | 普通表单控件创建、尺寸及同行按钮 |
| `MobileModalInput.css` | 键盘编辑器、数量确认弹窗的独立尺寸 |

冒险工具使用共享的桌面业务 DOM，通过 `AdventureMenuLayout.css` 在移动宿主内适配，不在桌面样式中增加移动断点。

### 底栏和操作组

- 实际底栏标记 `menu-footer`，仅这一层负责高度与上下 padding；嵌套的 `menu-action-group` 不再贡献第二份底栏留白。
- 普通操作使用 `menu-footer--trailing`；左侧点数、右侧按钮采用 `menu-footer--split`，右侧组使用 `menu-action-group--trailing`。
- 邮件手机竖屏将外层设为 `display: contents`，实际底栏标记在 `menu-footer--portrait` 上；横向布局（含平板竖屏）仍由外层 `menu-footer` 负责。
- 添加好友、邀请入队等依赖输入的按钮留在 `menu-form-row` 内，退出、删除等独立操作才进入底栏。
- 不用具体菜单名称扩充公共底栏选择器，也不把所有 `inventory-actions` 都当成底栏。

### 底部标签行

- `menu-bottom-tabs` 表示底部标签行；`menu-bottom-tabs--stacked` 仅手机上下布局启用。
- 公共组件负责标签上下各 6px 的内留白，并抵消紧邻底栏前的容器间距；业务文件只负责 `order` 或 `grid-row`。
- 社交横竖屏使用底部标签；装备和设置仅手机竖屏使用底部标签；平板两个方向都沿用横向布局的标签位置。

### 表单控件

- 普通字段通过 `createMenuField()` 创建，静态模板使用 `data-menu-control="field"`；普通字段独立边框与圆角由公共样式负责。
- 连体框的输入段使用 `createMenuField('input', 'segment')`，保留组件自身的拼接边框；不要给输入段加普通字段外框。
- 普通菜单控件共用 `--panel-control`（compact 30px、spacious 44px），同一行的操作按钮在 `menu-form-row` 内共享高度。
- 宽度、输入验证、事件处理由业务菜单负责。多行文本、文件选择、复选框、滑块及确认弹窗不套用普通字段边框规则。
- 下拉选中项使用单行省略，展开列表仍可显示完整文本。列表项、图标按钮不当作表单按钮统一尺寸。

新增规则前先确认归属；替换旧实现时同时删除旧规则，不通过增加选择器层级长期叠加修补。

### 平板方向与菜单布局

- `data-orientation` 表示真实屏幕方向，用于窗口高度、通知避让和键盘编辑器位置。
- `data-menu-arrangement` 是菜单结构的唯一判断：手机竖屏为 `stacked`，手机横屏和平板两个方向均为 `wide`。菜单列布局、底栏与标签位置不得直接判断屏幕方向。
- 沿用屏幕短边 600px 的手机判断，平板保持 `spacious` 控件密度，避免旋转时字号和按钮尺寸变化。
- 平板竖屏标准窗口使用可用区域的 72% 高度，横屏保留 640px 上限；NPC 对话、信息窗口及拾取搜索弹窗的高度上限同步缩短约 20%；短内容窗口仍按内容自适应。
- `menu-bottom-tabs--stacked` 仅在上下布局中启用底部标签间距；不再按平板竖屏启用。

### 平板按钮尺寸层

`MenuButtonSizing.css` 在功能布局和公共表单之后加载，由 HUD 与冒险工具共同引用，仅匹配非手机的移动菜单宿主。集中管理四类按钮，业务文件负责排列，不再另加平板按钮宽度补丁。

- 普通文字操作：最小宽度 `4em + 24px`、左右留白 12px、44px 高；按内容宽度排列，长文案自然增长。隐藏按钮仍保持隐藏。
- 返回／关闭：最小宽度 64px，文字显式居中；tab 保留原来的等分或内容宽度，仅统一内边距和对齐。
- 翻页：快捷键、邮件、冒险工具和拾取弹窗统一 44px 方形按钮，箭头字号 22px。
- 仓库／手推车数量组：四个按钮等宽 44px，输入区域伸缩，保留连体边框。
- 职业表单的等分按钮、加点按钮、列表项、下拉选项、数量弹窗和银行转移箭头保留各自结构，不套用普通操作按钮规则。

手机已有尺寸暂由 `MenuActionButtons.css` 等规则保留，平板差异集中在公共尺寸层；不复制菜单渲染代码，也不改桌面端样式。

分页容器必须标记 `data-menu-pagination`，公共尺寸层不再枚举各菜单分页类名。拾取弹窗在平板显示方向符号，按钮的 `aria-label` 保留上一页／下一页说明。

冒险工具职业操作组使用 `data-menu-action-layout="job"`，下方表单操作组使用 `data-menu-action-layout="columns"`。平板角色表单、职业操作组与表单操作组共用 `--tablet-character-columns`：详情面板默认一列，宽度达到 420／620／820px 时分别为二／三／四列。外层职业列表与详情保持左右布局；长职业名称允许换行，整行随内容增高。业务类名继续负责颜色与结构，公共尺寸按显式角色处理。

独立于底栏的普通操作按钮通过 `data-menu-button="action"` 接入公共平板尺寸，快捷键保存和取消已使用此标记。伴侣技能操作按业务类型渲染，仅生命体提供学习／升级按钮，不再通过手机 CSS 隐藏佣兵按钮。宠物和生命体名称输入框统一保留 placeholder 与 `aria-label`，不渲染重复的外部标题。

### 平板窄窗口

`MenuNarrowTablet.css` 由 HUD 和冒险工具共用，在按钮尺寸层后加载。仅对非手机宿主生效，按 `menu-window` 的实际宽度判断，不使用屏幕方向切换内容布局。

- 窗口小于 560px 时，工具栏和底栏允许换行；仓库／手推车数量组独占可用行宽，转移按钮另行排列。保留 44px 触控尺寸。
- 背包搜索、仓库搜索、邮件搜索和附件筛选可以分行，内容区域继续左右排列。邮件工具栏使用 Grid：窄窗口搜索跨满一行，分类／刷新与写信位于下一行。标题栏过宽时横向滚动。
- 冒险工具窗口小于 600px 时显式保留列表和详情，覆盖旧窄窗口选中后隐藏列表的样式。
- 冒险工具窗口小于 560px 时，掉落倍率表格取消固定最小宽度，数值框随单元格收缩。
- 手机与桌面端不受这些平板规则影响；平板角色表单按详情实际宽度适配，全屏与分屏共用同一规则。内容详情继续使用内部滚动，不通过整体缩小字体挤入窗口。

平板游戏 HUD 与菜单共用 `data-menu-arrangement`，横竖屏均采用 `wide`：状态区、小地图和聊天预览保持横向规则；真实方向继续用于窗口高度和通知避让。点数框、列表边框、宠物进化提示与操作行、商店金额格式和摊位状态文案在手机／平板共用，控件尺寸仍按密度区分。

冒险工具的列表返回按钮同步监听宿主布局属性及窗口宽度：平板 `wide` 模式始终同时展示两栏，不显示列表返回按钮；手机保留原有 600px 图鉴切换规则。返回主菜单与关闭按钮独立管理，不受此规则影响。

### 平板聊天预览自适应

`ChatPreviewLayout.js` 测量聊天左边缘到战斗区左边缘的可用空间，保留 12px 间距，预览宽度上限 420px。空间低于 240px 时临时收起，恢复到 256px 后解除临时收起，避免阈值附近反复切换。手机不使用此规则。

临时收起与 `ChatPreview.collapsed` 用户偏好分离：窄窗口点击入口直接打开聊天窗口，不保存展开设置；窗口变宽后按原偏好恢复。手动收起的预览继续收起。分类标签在缩窄时可横向滚动，原有私聊未读提醒继续使用同一入口。

平板素质加点编辑区按 `attribute-pane` 宽度适配：小于 360px 时，加点按钮组独占属性信息下方一行；小于 240px 时，点数消耗另起一行。数值允许换行，保留按钮触控高度与外层左右布局。

`AttributesMenuLayout.css` 单独处理平板真实竖屏的素质菜单：六项属性各自使用独立边框，框间距 14px，信息行最小高度 34px；属性信息与加点按钮固定分行，名称／数值／消耗采用三等分列宽，与下方三个加点按钮逐列对齐，单元格使用分隔线；长数值换行时各属性记录统一撑高以保持行对齐；相关属性及剩余点数限制在各自区域内。该规则不作用于平板横屏、手机或其他菜单。

`ContainerMenuLayout.css` 仅在平板竖屏手推车中将子类放在右半区搜索框左侧；工具栏与下方内容共用两等分列和 6px 间距，左右控件对齐对应内容框。

手推车卸下动作由 `GameContainers.js` 校验并发送协议，手机和平板共用 `ContainerPanel.js` 的确认入口；界面以服务端手推车状态更新可用性。手机竖屏数量组独占一行，确认转移与卸下按钮在下一行靠右排列。

装备菜单的骑乘解除由 `GameEquipment.js` 校验并发送协议，`EquipmentPanel.js` 在存在坐骑、机甲或猎鹰时显示对应确认按钮。状态以服务端回传为准；解除请求不重复发送，确认时校验骑乘状态，避免状态变化后误卸手推车。
