# 移动端认证与屏幕方向

手机和平板的登录、选角和创建角色页面使用 `UI/Mobile/` 组件，通过移动端 bootstrap 注册，复用公共角色业务逻辑。页面按可用宽高调整排列，旋转不重新挂载组件，因此保留输入、角色选择和外观设置。软键盘使用 `visualViewport` 调整面板位置与高度，布局宽度始终使用设备布局视口，失焦后清除键盘偏移；长内容在面板内原生滚动。选角与创建角色使用浅色主题。

登录与游戏场景均支持横竖屏，不设置横屏门禁或竖屏操作遮罩。旋转保留面板、角色选择和输入草稿；布局与输入编辑器按[菜单布局](mobile-menu-layout.md)的密度、方向及实际内容宽度调整。会话与断线恢复见[连接恢复](../network/connection-recovery.md)。

设备方向取自屏幕方向信息，软键盘引起的视口缩小不会被当成旋转。PWA 游戏入口在启动时声明设备视口，移动端固定根页面并锁定浏览器缩放、页面滚动和回弹，对页面内容启用尺寸与绘制隔离，防止旧游戏画布在旋转后撑大布局视口。双指事件仅取消浏览器默认行为，继续传给游戏手势处理；表单和角色列表保持原生单指滚动。

验证包括移动端认证组件、键盘可视区域、方向判断测试；浏览器需检查横竖屏布局、原生滚动、输入状态保留、竖屏进入游戏、横竖屏切换、游戏中旋转及返回选角。iOS 软键盘行为仍需真机验收。

移动端背景由 `UI/Mobile/Background.js` 提供纯色底层及资源／地图加载进度，不读取桌面登录拼图或随机加载壁纸；`UI/Mobile/WinLoading.js` 负责登录与角色服务器连接等待。两者使用 `Loading.css` 的浅色样式，真实资源进度与不定连接等待分别展示。桌面端继续使用原背景和弹窗。连接失败先移除等待界面，再显示错误信息。

移动端选角不提供预约删除、取消预约或确认删除；需要删除角色时使用桌面端。共享选角组件通过 `deletionEnabled` 控制删除能力，移动端关闭，桌面端保持启用。

创建页发型选项直接复用桌面端对应种族、性别的独立发型位图，不显示人物。`AppearancePreviews.js` 从桌面端发色色块中心取色，生成无位图边框的纯色色块；选项不再需要额外精灵渲染循环。空角色提示由共享选角组件每次更新角色槽时同步显隐，不依赖名称的 CSS 空值匹配。

公共 `UIManager.showMessageBox`、`showPromptBox`、`showErrorBox` 在移动端统一使用 `MessageDialog`，桌面端保持原实现。模态框初始焦点位于标题，按钮不会默认选中，键盘事件不传到底层游戏；关闭回调仅在用户操作时触发，程序移除不触发确认。每次新登录的角色列表初始化都会选中第一个角色位，普通角色列表分包更新不重置选择。

## 前端日志侧栏

默认不显示「日志」按钮，也不安装网络、控制台或错误监听。仅在页面 URL 带 `debug=1` 时启用并立即开始记录：

- 从启动页进入：`/applications/pwa/index.html?debug=1`，点击「进入游戏」会传递调试开关。
- 直接进入游戏：`/applications/pwa/api.html?app=ONLINE&debug=1`。

启用后，页面最右侧中部「日志」按钮打开调试侧栏。「记录日志」复选框只暂停或恢复本页记录；移除地址中的 `debug` 参数并刷新即可完全关闭，不受以前保存的开关状态影响。带参数刷新会重新启用，侧栏记录保存在页面内存中，刷新清空；若 Gateway 配置了 `HAPPYRO_GATEWAY_CLIENT_DIAGNOSTICS_DIR`，还会批量回传到同源 `/api/client-diagnostics`。上传容量、去重与退避以 Client 的 debug-upload 和 Gateway 接收器为准，日志不是只留在浏览器内。

覆盖应用模块加载前的错误、未处理 Promise 异常、控制台 log/info/warn/error、HTTP 请求状态和耗时、资源加载、WebSocket 创建/打开/错误/关闭和收发字节数、界面切换、视口与页面生命周期，每 5 秒追加状态快照。可复制、下载或手动记录当前状态；HTTP 下自动使用选区复制全文；两种复制方式均被浏览器拒绝时保留全文选区，可长按复制或下载文本文件。

工具不记录请求正文、响应正文、封包正文、请求头或任意对象内容，移除 URL 查询参数并隐藏捕获的输入值和常见敏感字段。日志仍包含服务器地址和浏览器信息。仅添加观测，不增加 WebSocket 连接延时、重试或超时逻辑。

## 提示弹窗主题

`MessageDialog` 根据 `Session.Playing` 选择主题：登录、选服和选角阶段与注册弹窗共享 `UI/Mobile/LoginDialog.css` 的亮色边框、标题和按钮；进入游戏后加载原游戏确认框样式。不要通过登录窗口是否仍在 DOM 中判断阶段，连接等待时登录窗口可能已经移除。返回选角或登录后恢复亮色，确认、取消、键盘和回调行为保持一致。
