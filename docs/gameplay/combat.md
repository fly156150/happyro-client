# 移动与自动战斗

[游戏行为索引](README.md)

## 摇杆停止

移动端摇杆松手或触摸取消时，`GameCommands.stopDirectionalMovement` 立即清除本地续走，并在本次拖动确实发送过方向移动时发送一次 `CZ_HAPPYRO_STOP_MOVE`（`0xd03`，仅 2 字节小端包头）。它不携带客户端坐标，也不改动持续行走的请求间隔、目标距离或动画。

HappyRO Server 沿当前路线缩短剩余步程，通过现有移动确认同步终点；网络往返与格子步进仍会影响停止时间。客户端与服务端须配套部署，先更新支持 `0xd03` 的服务端，再更新客户端，`PACKETVER` 保持 `20211103`。

自动战斗的客户端追击也使用 `0xd03` 停步：先取消排队攻击，再请求服务器缩短当前路线，避免把显示位置取整后作为新的移动目标而导致回退。

## 桌面与移动端自动战斗

- `UI/Game/AutoCombatController.js`：不依赖 DOM 的战斗策略，负责目标筛选、范围约束、追击超时、技能选择及暂停／恢复。
- `UI/Game/GameAutoCombat.js`：连接实体、寻路、服务器封包和按服务器／账号／角色隔离的配置存储。
- `UI/Game/GameAutoCombatRuntime.js`：两端共用的地图会话运行层，统一定时驱动、输入接管、页面失焦／隐藏、死亡与断线清理。每次地图挂载创建一个实例，离开地图销毁；不持久化“正在战斗”状态。
- `Controls/GameInputIntent.js`：手动输入意图通知，不依赖具体 HUD。地图点击、技能快捷键、导航与实体手柄通过它让出或接管控制权；自动战斗直接调用运行适配器，不会把自己的攻击当作手动输入。
- `UI/Game/AutoCombatPanel.js` / `.css`：两端共用的魔物种类、技能与范围编辑器。桌面 `UI/Components/AutoCombat/` 只负责控制条和设置对话框，手机 HUD 只负责触摸入口与布局。

桌面右下角依次为自动战斗、自动拾取、设置三个图标按钮。战斗与拾取独立启停，开启时使用绿色背景和边框，无状态点；悬停提示说明下一次点击的动作。齿轮打开参数窗口，窗口内不重复显示总开关或启停状态，打开或关闭窗口不改变运行状态。未选技能时普攻，所选技能均不可用时回退普攻；范围内无目标则等待；启用无目标随机瞬移且具备权限时，在没有可拾取物品后按配置请求随机安全落点，具体协议见[导航](navigation.md)。自动战斗开启时点击魔物可切换目标；未开启时保留桌面原有点击攻击行为。左键移动期间暂停，松开且角色停步后继续，并重设活动起点；手动施法、NPC／物品操作、导航会停止自动战斗。页面失焦或隐藏、死亡、切图、断线后均需手动重新开始。物理手柄移动与手机摇杆复用同一暂停策略。

自动战斗只使用现有游戏封包，所有伤害、技能消耗、冷却和移动结果仍由服务端决定。浏览器失焦会主动停止，无法作为后台挂机进程运行。
