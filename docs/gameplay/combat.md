# 移动与自动战斗

[游戏行为索引](README.md)

## 摇杆停止

移动端摇杆松手或触摸取消时，`GameCommands.stopDirectionalMovement` 立即清除本地续走，并在本次拖动确实发送过方向移动时发送一次 `CZ_HAPPYRO_STOP_MOVE`（`0xd03`，仅 2 字节小端包头）。它不携带客户端坐标，也不改动持续行走的请求间隔、目标距离或动画。

HappyRO Server 沿当前路线缩短剩余步程，通过现有移动确认同步终点；网络往返与格子步进仍会影响停止时间。客户端与服务端须配套部署，先更新支持 `0xd03` 的服务端，再更新客户端，`PACKETVER` 保持 `20211103`。

自动战斗的客户端追击也使用 `0xd03` 停步：先取消排队攻击，再请求服务器缩短当前路线，避免把显示位置取整后作为新的移动目标而导致回退。

## 桌面与移动端自动战斗

- `UI/Game/AutoCombatController.js`：不依赖 DOM 的战斗策略，负责目标筛选、范围约束、追击超时、技能选择及暂停／恢复。
- `UI/Game/GameAutoCombat.js`：连接实体、寻路、服务器封包和按服务器／账号／角色隔离的配置存储。
- `UI/Game/GameAutoCombatRuntime.js`：两端共用的地图会话运行层，统一定时驱动、输入接管、页面失焦／隐藏、死亡与断线清理。每次地图挂载创建一个实例，离开地图销毁；不持久化“正在战斗”状态。
- `Controls/GameInputIntent.js`：手动输入意图通知，不依赖具体 HUD。地图点击、技能快捷键、导航与实体手柄通过它让出或接管控制权；自动战斗直接调用运行适配器，不会把自己的攻击当作手动输入。
- `UI/Game/AutoCombatPanel.js` / `.css`：两端共用的魔物种类、技能与范围编辑器。桌面 `UI/Components/AutoCombat/` 只负责控制条和设置对话框，手机 HUD 只负责触摸入口与布局。

桌面右下角依次为自动战斗、自动拾取、设置三个图标按钮。战斗与拾取独立启停，开启时使用浅黄色背景和边框，关闭时灰色且为 70% 不透明度，无状态点；悬停提示说明下一次点击的动作。齿轮打开参数窗口，窗口内不重复显示总开关或启停状态，打开或关闭窗口不改变运行状态。未选技能时普攻，所选技能均不可用时回退普攻；范围内无目标则等待；启用无目标随机瞬移且具备权限时，在没有可拾取物品后按配置请求随机安全落点，具体协议见[导航](navigation.md)。自动战斗开启时点击魔物可切换目标；未开启时保留桌面原有点击攻击行为。左键移动期间暂停，松开且角色停步后继续，并重设活动起点；手动施法、NPC／物品操作、导航会停止自动战斗。页面失焦或隐藏、死亡、切图、断线后均需手动重新开始。物理手柄移动与手机摇杆复用同一暂停策略。

自动战斗只使用现有游戏封包，所有伤害、技能消耗、冷却和移动结果仍由服务端决定。浏览器失焦会主动停止，无法作为后台挂机进程运行。

## 按目标选择技能与失败兜底

`CombatSkillAffinity.js` 根据当前目标的魔物 ID、已选技能和习得等级判断适用性。优先顺序为有效克制、普通适用、受属性减伤；同一类比较属性倍率，再比较已核实的种族／体型加成，完全相同时随机。属性倍率小于等于零、目标条件不符或已知技能免疫时排除该技能。武器／赋予属性、混合属性和依赖状态的覆盖不推断为固定属性；不直接伤害的控制／防御技能不套用伤害属性倍率；转为攻击不死的辅助技能等已核实例外单独处理。这是择技偏好，不是总伤害预测。

基础资料位于 `applications/pwa/data/combat/affinities.json`，来自同工作区当前 Renewal 的技能库、魔物库、四级属性表和不死判定配置，保留来源哈希。特殊规则按服务端对应技能实现审核，包含对不死的攻击性辅助技能、动物／昆虫限定、种族加成与连刺体型加成；石化术排除状态免疫目标，华丽金属只允许服务端明确标记可作用的技能；光耀之堂只用于不死或恶魔目标，避免治疗其他魔物。导入目录存在覆盖时生成器会停止，要求先审查实际规则。

```bash
npm run catalog:combat -- generate --output ../../work/combat-affinities.json --no-color
npm run catalog:combat -- check --output applications/pwa/data/combat/affinities.json --no-color
```

生成后先审查工作目录产物与服务端语义，再安装到产品资料路径并完整构建 PWA。无参数仅显示帮助。修改特殊技能实现后同步审核 `CombatSkillRules.js`；来源哈希只能发现变化，不能代替语义审核。

失败状态按当前目标与技能记录，10 秒后可重试。同步失败、`ACK_TOUSESKILL`／`USE_SKILL` 失败反馈及本角色 `DISPEL` 施法中断会让出本次技能；其他技能也不可用时普攻，不把单个技能失败当作魔物不可达。`SkillExecution.js` 将本角色的失败、读条和执行回包传给运行期，销毁／断线时取消订阅。

每次只保留一个待确认技能；读条结束后仍等待执行回包，避免伤害回包稍晚时重复发送。请求没有执行确认时，8 秒看门狗触发 3 秒普攻窗口；服务器读条延长到实际施法结束后 8 秒，接近目标时有位置进展也会延长等待。只清理已过期的本地读条，不移除正在进行的施法。目标切换与手动操作清理待确认状态；停止或没有待确认施放时忽略回包，无关技能结果不参与当前判断。原有不可达目标超时策略仍独立生效。

## 规则扩展与职责边界

- `CombatSkillRules.js`：以服务端技能名注册特殊规则。`requiresKnownMonster` 控制是否必须确认魔物资料，`canTarget(context)` 决定目标是否合法，`bonus(context)` 标记已核实加成，`offensiveSupport` 开放攻击性辅助技能，`convertsDamage` 标记无伤害入口转为伤害的例外。生成器和运行期共享这份定义。
- `CombatSkillAffinity.js`：纯评分管线，依次执行通用免疫检查、特殊目标条件、属性倍率、额外加成；硬性排除条件不会被高倍率覆盖。`createCombatSkillPolicy(catalog, rules)` 可注入独立资料与规则测试，不修改全局注册表。当前产品只创建一份默认策略。
- `AutoCombatSkillState.js`：独立的施法恢复状态机。时长统一在 `AUTO_COMBAT_SKILL_TIMING`，调用方传入单调时钟；模块不启动定时器、不发送封包、不操作界面。失败暂避按目标和技能隔离；停止重置全部状态，换目标清理待确认施法。
- `AutoCombatController.js`：组合目标搜索、评分器与状态机，并执行停止、普攻和状态文案等副作用；`GameAutoCombat.js` 继续负责实体与封包适配。

新增规则时只在规则表加入对应技能名及所需字段，并以实际服务端逻辑为依据；补充目标允许／禁止和与其他技能竞争的测试。涉及资料字段或 `convertsDamage` 时重新生成并校验快照。不得在评分规则中调用网络、读取 UI 或修改恢复状态；未知武器属性与实时状态仍不猜测为确定克制。
