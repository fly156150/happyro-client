# 移动端菜单布局

所有游戏子菜单共享 `src/UI/Mobile/game/MenuLayout.css`，分类与浮层边界计算位于 `MenuLayout.js`。业务样式只负责窗口内部排版，不再定义外框尺寸或独立的设备断点。

## 尺寸策略

可用布局视口宽至少 768、高至少 560 CSS 像素时使用 spacious，其余使用 compact。分屏和旋转重新判断；软键盘打开期间保持原密度，窗口适配可视高度。

| 窗口 | 平板上限 | 手机 |
| --- | --- | --- |
| 普通子菜单、冒险工具 | 1040×640 | 保留紧凑尺寸，受安全区域约束 |
| 主菜单 | 宽 560，高 640 | 宽 420，内容自适应 |
| 确认、消息弹窗 | 420×480 | 同样受可视区域约束 |
| 装备选择弹窗 | 宽 640 | 同样受可视区域约束 |
| 输入编辑器 | 宽 420，单行高 160、多行高 320 | 竖屏居中卡片，横屏全屏顶部输入条 |

所有尺寸均为上限；边距、安全区域和键盘可视高度优先。普通子菜单平板统一高度；短确认弹窗按内容缩小。

## 接入规则

- 外层使用 `mobile-menu-viewport`，窗口使用 `mobile-menu-window`；在业务样式之后加载 `MenuLayout.css`。
- 宿主通过 `createMobileViewport` 或 `bindMobileViewport` 更新视口和密度，销毁时释放监听。独立消息弹窗使用 `mobile-menu-dialog`。
- 标题和操作栏不能收缩；可滚动内容必须设置 `min-height: 0`，滚动发生在内容内，不能让整个窗口超出视口。
- 控件使用 `--panel-control`、`--panel-label`、`--panel-heading`、`--panel-gap`。需要调整统一尺寸时仅修改中心样式中的 token；手机特殊宽度也集中登记在这里。
- 冒险工具内部列布局使用 `menu-content` 容器查询，逻辑通过 ResizeObserver 读取实际窗口宽度，不能根据设备宽度猜测内容宽度。
- 菜单和冒险工具下拉框共用 `GameSelectLayout.js`，使用 Popover 顶层显示，按可视视口限高，优先向下展开，允许超出小弹窗边界，避免被滚动容器或 containment 裁切。视口平移／缩放、外部点击、父容器滚动及窗口销毁时关闭浮层；列表自身滚动保持展开。

## 验证

覆盖窄屏竖屏、手机横屏、平板横竖屏、桌面尺寸下的移动 UI、分屏及低高度视口；检查最长内容、下拉框、二级弹窗及键盘开合。PWA 必须使用 `npm run build:pwa` 完整构建，保留启动页与全部查看器。

## 字号与组件密度

字号和通用控件尺寸由 `MenuLayout.css` 统一定义；冒险工具与其它子菜单共用，不再定义独立的字号比例。业务样式根据内容角色选用变量，不根据具体文案单独加大或缩小。

| 角色 | 共享变量 | 手机 | 平板 |
| --- | --- | --- | --- |
| 正文、详情说明 | `--panel-text` | 12px | 16px |
| 分节标题 | `--panel-heading` | 12px | 16px |
| 窗口主标题、详情名称 | `--panel-title` | 14px | 18px |
| 辅助信息、字段标签 | `--panel-label` | 11px | 14px |
| 次要提示 | `--panel-caption` | 10px | 14px |
| 通用按钮、输入框高度 | `--panel-control` | 30px | 44px |
| 素质加点按钮高度 | `--panel-attribute-control` | 26px | 44px |
| 素质加点按钮宽度 | `--panel-attribute-width` | 32px | 56px |

- NPC、出现地图、掉落物品、职业、等级与点数等均属于分节标题，不能各自硬编码字号。
- 按钮内边距使用 `--panel-control-padding`；布局间距使用 `--panel-gap`。表格、列表和分栏仍由业务样式负责排版。
- 图鉴列表、魔物详情、物品详情的图片尺寸和缩放参数集中登记为 `--panel-list-image-scale`、`--panel-detail-image`、`--panel-detail-image-scale` 和 `--panel-item-image`。精灵图原始裁切尺寸保持不变，通过等比缩放放大，避免错位。
- 箭头等图形字符可保留自己的视觉尺寸；它们不属于正文排版。聊天等既有专用控件可保留已定义的功能布局。

手机宠物、生命体、佣兵和银行与背包等普通子菜单共用 780px 宽度上限及安全区域内全高；生命体与佣兵共用 companions 窗口，不再保留 420px 小窗例外。

## 按内容宽度自适应

`MenuLayout.js` 统一维护宿主的 `data-menu-density` 和 `data-orientation`。密度决定字号与控件大小，方向决定 HUD 和窗口高度，均不能直接替代内容宽度。`MobileViewport.js` 在软键盘打开时保留布局方向和密度，只更新可视高度；旋转或分屏改变布局宽度后重新计算。

游戏 HUD 与冒险工具在业务样式最后加载 `MenuContentLayout.css`。这是移动端公共分栏的统一入口，使用命名容器查询；随后加载 `MenuContentComponents.css`，处理具体组件的工具栏、边框、图片和详情排版；`MenuPortrait.css` 仅保留方向相关的窗口高度、拾取弹窗尺寸与操作排列。不要通过设备名称或竖屏状态推断是否需要上下布局。

| 容器 | 可用宽度 | 布局规则 |
| --- | --- | --- |
| `menu-window` | 小于 640px | 背包、装备、技能、快捷键、邮件、冒险工具上下排列；列表和详情同时显示，各自滚动；聊天筛选栏横排，输入框单独一行 |
| `menu-window` | 640px 及以上 | 普通列表/详情恢复左右排列；技能与快捷键候选始终保持两列卡片 |
| `menu-window` | spacious 密度、小于 800px | 素质、自动战斗配置保留上下排列，为较大的表单控件留足宽度；compact 密度采用 640px 阈值 |
| `menu-window` | spacious 密度、640～899px | 商店、交易、精炼等三栏流程采用上方两栏、下方详情；两栏仓库保持左右布局；900px 起保留完整多栏 |
| `menu-detail` | 小于 540px | 地图/NPC 详情内部地图与说明上下排列，魔物资源单列；不改变外层列表/详情分栏 |
| `menu-detail` | 小于 460px / 360px | 角色维护表单改单列 / 图片和长描述上下排列 |
| `shortcut-slot` | 单个按钮内容宽度小于 64px | 仅显示位置数字；空间足够时恢复完整位置与绑定名称，始终保留完整无障碍标签 |

高度与滚动：标准竖屏工作窗口占安全区内约 96% 高度，首页按内容自适应；双区域各自滚动，多区域窄屏流程纵向滚动，操作区始终可达。旋转、分屏与窗口缩放只更新样式，不重建业务组件，不丢失选中项、预加点和输入草稿。

拾取搜索弹窗宽度上限为手机 420px、平板 640px，竖屏高度统一为可视区域的 80%；数量和页码在上，上一页、下一页、取消、确认添加在同一行。按钮沿用共享尺寸，横屏保留原规则。

游戏顶部通知使用 HUD 实际底边提供的共享通知位置，避开人物信息、小地图和方向提示条；横屏和 HUD 移除后恢复原位置。

验收覆盖 320×568、390×844、507×1024（平板分屏）、600×960、768×1024、820×1180、1024×1366，以及 844×390、1024×768 横屏。检查外层与内层分栏、横向溢出、操作区和滚动可达性、切换后的选中状态。复杂交易流程还需在实际容器宽度与控制密度组合下单独验证。

## 新组件的布局接入

外框、密度、方向仍由 `MenuLayout.js` / `MenuLayout.css` 管理。内容分栏通过组件声明选择，公共 CSS 不再枚举背包、装备等业务类名。

| 声明 | 内容结构 | 适用场景 |
| --- | --- | --- |
| `data-menu-layout="split"` | 两个直接子区域 | 列表＋详情；窄窗口上下各占一半 |
| `data-menu-layout="form"` | 两个直接子区域 | 表单＋结果；宽松密度采用 800px 阈值 |
| `data-menu-layout="columns"` | 两栏或三栏 | 仓库、交易、精炼等流程 |
| `data-menu-layout="shop"` | 列表、操作区、订单、详情 | 带中间操作区的商店流程 |

例如：

```html
<div class="example-layout" data-menu-layout="split">
  <section class="example-list">列表</section>
  <section class="example-detail">详情</section>
</div>
```

组件负责宽屏默认列比例、内容和自身装饰；公共布局负责现有断点下的列切换、区域约束和滚动。不要为新业务组件在公共布局里追加类名，也不要复制一套设备判断。

多栏流程通过 `interactionColumns(body, columns)` 创建，该函数自动声明布局及 `data-menu-columns`。两栏模式的宽屏样式和中等宽度行为都从同一个列数声明读取，调用方无需额外添加“两栏”样式类。

样式顺序固定为：业务基础样式 → 共享外框与控件 → 方向相关样式 → `MenuContentLayout.css` → `MenuContentComponents.css`。公共文件只维护布局协议；专属规则在组件文件中调整，避免让新组件隐式继承其它业务的图片或按钮样式。本轮重构保留原有断点、选择器权重、尺寸与视觉值。

手机端冒险工具物品页的顶部搜索栏固定两行：第一行搜索，第二行类型、子类和发放 Zeny。`AdventureTools.js` 依据屏幕短边小于 600 CSS 像素设置局部 `data-phone-screen` 标记，仅用于该搜索栏；平板窄分屏与软键盘不会因此套用手机规则，窗口尺寸及其它内容继续遵循共用布局。

## 样式职责与复用

移动菜单的样式按以下顺序加载，后面的菜单规则只负责内容排列，不重新定义公共控件高度。

| 文件 | 职责 |
| --- | --- |
| `MenuLayout.css` | 视口、密度、字号及尺寸变量 |
| `MenuChrome.css` | 标题栏、底栏高度、按钮组与内容区边界 |
| `MenuFeatureStyles.js` 与各 `*MenuLayout.css` | 各菜单横竖屏排列、滚动区域与业务内容 |
| `MenuBottomTabs.css` | 底部标签行的分隔线与对称留白 |
| `MenuFormControls.js` / `.css` | 普通表单控件创建、尺寸及同行按钮 |
| `MobileModalInput.css` | 键盘编辑器、数量确认弹窗的独立尺寸 |

冒险工具使用共享的桌面业务 DOM，通过 `AdventureMenuLayout.css` 在移动宿主内适配，不在桌面样式中增加移动断点。

### 底栏和操作组

- 实际底栏标记 `menu-footer`，仅这一层负责高度与上下 padding；嵌套的 `menu-action-group` 不再贡献第二份底栏留白。
- 普通操作使用 `menu-footer--trailing`；左侧点数、右侧按钮采用 `menu-footer--split`，右侧组使用 `menu-action-group--trailing`。
- 邮件竖屏将外层设为 `display: contents`，实际底栏标记在 `menu-footer--portrait` 上；横屏仍由外层 `menu-footer` 负责。
- 添加好友、邀请入队等依赖输入的按钮留在 `menu-form-row` 内，退出、删除等独立操作才进入底栏。
- 不用具体菜单名称扩充公共底栏选择器，也不把所有 `inventory-actions` 都当成底栏。

### 底部标签行

- `menu-bottom-tabs` 表示底部标签行；`menu-bottom-tabs--portrait` 仅竖屏启用，`menu-bottom-tabs--phone-portrait` 仅手机竖屏启用。
- 公共组件负责标签上下各 6px 的内留白，并抵消紧邻底栏前的容器间距；业务文件只负责 `order` 或 `grid-row`。
- 社交横竖屏使用底部标签；装备竖屏使用底部标签；设置仅手机竖屏使用底部标签。不要把这些布局条件合并为一个设备条件。

### 表单控件

- 普通字段通过 `createMenuField()` 创建，静态模板使用 `data-menu-control="field"`；普通字段独立边框与圆角由公共样式负责。
- 连体框的输入段使用 `createMenuField('input', 'segment')`，保留组件自身的拼接边框；不要给输入段加普通字段外框。
- 普通菜单控件共用 `--panel-control`（compact 30px、spacious 44px），同一行的操作按钮在 `menu-form-row` 内共享高度。
- 宽度、输入验证、事件处理由业务菜单负责。多行文本、文件选择、复选框、滑块及确认弹窗不套用普通字段边框规则。
- 下拉选中项使用单行省略，展开列表仍可显示完整文本。列表项、图标按钮不当作表单按钮统一尺寸。

新增规则前先确认归属；替换旧实现时同时删除旧规则，不通过增加选择器层级长期叠加修补。
